## 1. Renewal viability spike (go/no-go gate)

- [x] 1.1 Spike outcome: FreeIPA 4.13 has **no native in-place renew** (`ipa-cert-renew` does not exist), and certmonger's IPA helper can only target the default CA `ipa`, so it cannot renew certs issued by our custom `kubernetes-ca` (ACL denial reproduced: "not permitted to use CA 'ipa'"). Adopted mechanism instead: **keytab-driven re-issue from the same key** via `ipa cert-request --ca=kubernetes-ca` — identity preserved because the profile rewrites the CSR subject and the existing private key is reused. Issuance verified on a worker's node cert (same subject/principal, later `notAfter`). Full in-place + service verification tracked under 4.1/6.1. **Gate passed with adjusted mechanism; design D2 updated.**

## 2. Profile / CA renewal enablement

- [x] 2.1 Profiles `kubernetesNodes` and `kubeAdministrators` accept re-issue from the existing key for each principal type, verified empirically: worker host TGT → `host/<node>` (profile adds `system:node:` prefix), master host TGT → `HTTP/<master>` and `host/<master>`, `kubeclusteradm` user keytab → `kubeclusteradm`. ACL `kubernetes-ca-acl` (bound to CA `kubernetes-ca`) grants the three hosts + `user category: all`; verified via `ipa caacl-show`.

## 3. Per-host timer provisioning

- [x] 3.1 Add a task that installs a persistent systemd timer on every host (master + all workers) running the renewal script for eligible certs, with per-host jitter to stagger reloads; verify the timer is active (`systemctl list-timers`) and set `Persistent=true`. Verified live: master/node1/node2 timers enabled+active with staggered next-trigger times (02:30/02:56/03:20) and `Persistent=yes`.

## 4. Post-renewal deployment + service reload

- [x] 4.1 Worker: after a renew, redeploy `/etc/kubernetes/pki/node-client.{crt,key}` and reload kubelet; verify the node stays Ready and the kubelet presents the renewed cert. Verified live on node1 (forced eligibility via `RENEW_THRESHOLD_DAYS=3650`): re-issue succeeded (new serial `0345D2...`, same subject `O=system:nodes, CN=system:node:node1.osgiliath.test`, later notAfter), kubelet restarted (`ActiveEnterTimestamp` advanced) and the node reports Ready with "kubelet is posting ready status" on the control plane. Also fixed a latent bug found during verification: the node-client `-addext` args carried literal single quotes that broke `openssl req` once unquoted expansion reached it (the path had never executed before, timer ticks were no-ops).
- [x] 4.2 Master admin: after a renew, update `kubeadm.crt` + `admin.conf` credentials; verify `kubectl` via `admin.conf` still authenticates with the renewed cert. Verified live on master (forced eligibility): re-issue from the kubeclusteradm keytab succeeded (new serial `E6058C...`, later notAfter), installed at `/home/kubecreds/kubeadm.crt` and re-embedded into admin.conf; `kubectl --kubeconfig=/etc/kubernetes/admin.conf auth can-i get nodes` → yes, namespace listing works. Also fixed a latent bug found during verification: `kinit -kt <keytab>` without an explicit principal falls back to the host principal, which is absent from the kubeclusteradm keytab — `request()` now takes an explicit kinit principal (defaulting to the host principal).
- [x] 4.3 Control-plane: redeploy component certs and restart the affected static pod(s) (API server / front-proxy), gated/staggered; verify the API server remains healthy after restart. Verified live on master (forced eligibility): apiserver + front-proxy-client re-issued and installed, kube-apiserver static pod restarted (new container, attempt 4); `/healthz` → ok, all nodes Ready, and `openssl s_client` against :6443 shows the API server serving the renewed cert (serial matches on-disk). This also proved the idm resolved-scope fix end-to-end: the IP-SAN CSR now passes IPA's `_validate_san_ips`.

## 5. Idempotency / no-churn

- [x] 5.1 Verify a timer tick with no eligible cert performs no cert rewrite and no service restart (no-op); confirm repeated ticks do not churn healthy components. Verified live on node1: `systemctl start kube-cert-renew.service` (the exact timer action) logged `not eligible, skipping ... 730d remaining (>= 30d threshold)` → `renewal tick complete`; cert mtime and serial unchanged, kubelet `ActiveEnterTimestamp` unchanged. A prior real timer fire (03:51 log entry) was likewise a no-op — repeated ticks churn nothing.

## 6. End-to-end verification

- [x] 6.1 Run the full cycle on a multi-worker cluster; verify timers are active on all hosts, then force/simulate an eligibility to confirm certs extend in place and services stay healthy (nodes Ready, `kubectl` via admin.conf working). Verified live on master + node1 + node2: all three `kube-cert-renew.timer`s enabled+active; forced eligibility (`RENEW_THRESHOLD_DAYS=3650`) extended every cert in place from its existing key — node-client on both workers (serials `0345D2...`/`2B2629...`, same subjects, later notAfter), apiserver + front-proxy + admin on master; kubelet restarted on both workers and the kube-apiserver static pod restarted once; afterwards all nodes Ready, `kubectl` via admin.conf authenticates (`auth can-i list pods` → yes), and :6443 serves the renewed serving cert.

## 7. Follow-up refinements (post-completion)

- [x] 7.1 Replace the shell `ipa role-add-member` task in `tasks/ipa-cert-renewal.yml` with the native `freeipa.ansible_freeipa.iparole` module (`action: member`, `host: [<master>]`) — removes kinit + password-on-stdin and fragile stdout matching; idempotency is now native (module diffs against `role_show --all`'s `member_host`). Verified live via playbook: adding a new host → `changed=1`; re-run with the member already present → `changed=0`, no spurious "already a member" failure.
- [x] 7.2 Add behavior tests for the renewal mechanism (in `molecule/default/tests/`, shared by all scenarios via symlink): master — a forced no-op tick (`RENEW_THRESHOLD_DAYS=1`) must not rewrite the apiserver cert or restart services; node — same no-churn assertion on the node-client cert, plus a forced-eligibility test (`RENEW_THRESHOLD_DAYS=3650`) asserting the serial changes and kubelet ends active (placed last since it restarts kubelet).
- [x] 7.3 Provision CA ACL host grants during converge: `kubernetes-ca-acl` was created with only `user category: all`, so on a fresh cluster renewal as a **host principal** (node-client, apiserver, front-proxy) is denied by the ACL ("not permitted to use CA 'kubernetes-ca'") — forced-eligibility tests failed on a clean converge. Added an idempotent task in `tasks/ipa-cert-renewal.yml` (master-only, delegated to idm) that grants every kube host (`groups[kube_masters_group] + groups[kube_nodes_group]`) to `kubernetes-ca-acl`, guarded by a `caacl-show` membership check. This implements the spec scenario "CA ACL permits each principal type" after convergence.
