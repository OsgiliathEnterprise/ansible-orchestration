## Why

The kvm (Travis CI) converge fails at `Kube-install-join | fail if join failed` (`tasks/kube-install-join-node.yml` rescue) with the generic message *"Node join failed - kubelet not active. Check kubelet logs above."* The Travis log names the dying task — the `kubernetesNodes` profile gate (`kube-install-join-node.yml:39`), 40 identical attempts with the profile genuinely absent — and the PIPELINE timing (31.5 min converge vs the node's 271 s gate window, master alive ~20 min past the node's death) closes the root cause as a **race**: the node's gate budget is too small for the master's profile-creation pace on the constrained CI runner. The master then dies at its first worker-dependent gate — the cascade, not the cause. Two defects made this undiagnosable from CI logs: the rescue reported only a 2000-line journal tail of a kubelet that never started (which misled this investigation), and every join-phase gate reports a generic timeout that names neither the phase nor the upstream dependency it waits on. `c5694a6` ("chore: remove the selfsigned kubernetes ca") **surfaced, not introduced**, the race: it added time to the master's pre-profile path, and the prior archived change was validated parallels-only. The join-gate fix shipped in #107 confirmed that mechanism end to end (gate waited its full join-scale budget, rescue + named fail with upstream evidence fired) — and exposed the *earlier* master-side death that #106's log had lost: the post-calico coredns restart died on a transient 504 from the just-initialized API server (`tasks/kube-install.yml:141`), aborting the master chain before profile creation. Both legs — node gate budget and master bring-up API-call resilience — are needed for the CI converge to complete. Build #108 (`d869e70`) proved both hardened tasks behave as designed (apply succeeded first try; rollout wait failed *by name* after 24 polls all reporting `unavailableReplicas: 3`) and exposed the fifth bucket: the calico-node Ready gate added after #107 was broken from the start — the pinned `kubernetes.core` rejects its `all_namespaces`/singular-selector parameters, `failed_when: false` swallowed the module error, the gate polled an empty list for its whole window, and its named fail killed the master chain before profile creation (see `evidence.md` #108 post-mortem).

## What Changes

- Root-cause fix: give the `kubernetesNodes` profile gate its own join-scale budget (dedicated vars, ~20 min ceiling sized ≥ 2× the measured CI pace) instead of the generic 40×5 s readiness pair, and make its timeout fail with a named diagnosis (`kubernetesNodes` missing + master-side producer task + captured `ipa certprofile-find` output) — see `evidence.md` for the measurement this budget is justified by.
- Harden the master's bring-up k8s-API calls feeding join readiness (fourth bucket, confirmed by build #107): the post-calico coredns restart — previously one un-retried `kubernetes.core.k8s` call whose 504 from the just-initialized API server aborted the master chain before profile creation — becomes an idempotent patch apply + `k8s_info` rollout poll, each with a bounded retry budget, `failed_when: false`, and a named fail attributing the upstream cause.
- Gate the coredns restart on this node's calico-node pod being Ready (fifth bucket, confirmed by build #108 + local cold reproduction): a `k8s_info` poll scoped to `namespace: calico-system` with the collection-supported **plural** `label_selectors`/`field_selectors` (the original gate used `all_namespaces` + singular params that the pinned module rejects — the swallowed arg error made it poll empty and kill the master chain), a named fail that self-reports the module error, and budgets (`kube_calico_node_ready_*` 90×10 s; `kube_join_profile_ready_retries` 180) sized so the master's worst-case pre-profile path fits under the node gate ceiling.
- Make the node's two delegated CA fetches (`ipa ca-show kubernetes-ca` and `ipa ca-show kubeclusteradm`, plus their slurps) **transient-resilient** (bounded retries) like the other IPA-dependent gates — they are hard fatals today.
- Replace the join-block rescue's generic message with a **structured per-phase diagnostic**: the failing phase name, the upstream dependency it was waiting on (idm CA availability / master API serving the IPA certificate), and the gate's last probe state; the journal capture must be **since block start** (`--since` timestamp), not a blind tail.
- Emit the join-phase post-mortem artifacts to the CI log from the Ansible `rescue:` itself (scenario-agnostic, no Travis config): `journalctl -u kubelet --since <block start>`, `crictl pods`/`crictl ps`, gate probe outputs, `ipa-getcert list` and keytab presence on the failing host.

## Capabilities

### New Capabilities

- (none)

### Modified Capabilities

- `kube-node-join`: adds requirements that (a) the profile readiness gate waits on a dedicated join-scale budget and fails with a named diagnosis plus captured `ipa certprofile-find` evidence, (b) the node's CA material fetches from FreeIPA retry transient IPA/API failures within a bounded budget before failing, (c) a failed join phase fails with a diagnosis naming the phase, the upstream dependency, and journal evidence captured since the join block started — never a generic "check kubelet logs", (d) the master bring-up API calls that feed join readiness (post-calico coredns restart) tolerate transient API-server 5xx within a bounded budget and fail by name otherwise, so one gateway timeout cannot abort the master chain and starve the node gate, and (e) the coredns restart is gated on this node's calico-node pod being Ready via a query that uses only collection-supported parameters and self-reports module-level query errors, with the gate + rollout budgets chained under the node gate ceiling.

## Impact

- Affected code: `tasks/kube-install-join-node.yml` (profile-gate budget + named-fail, fetch retries, rescue diagnostics); `defaults/main.yml` (join-gate budget vars, calico-node gate budget vars, join budget raised to the measured CI worst case); `tasks/kube-install.yml` (coredns restart split into resilient apply + rollout poll with named fails; calico-node Ready gate with collection-supported query params and self-reported module errors); `tasks/drain-and-reset.yml` (reset-path drain flags nested under the module-supported `delete_options:` — the flat forms were rejected by the pinned collection and silently swallowed by `failed_when: false`, same param-discipline class, found in the #109 log). No `tasks/certs/*` change (the struck master-chain bucket), no Travis config — diagnostics run in the rescue path (design D2).
- Test/CI: `molecule/default/tests/test_node.py` gains structural assertions on the rescue diagnostic output; `molecule/default/tests/test_master.py` gains the static guards pinning the coredns load-tolerance contract and the calico-node gate (namespace + plural selector params pinned, singular/`all_namespaces` forms banned as the #108 bug class); no interface or variable renames.
- Root-cause tasks are collapsed to the evidence-matched bucket (node profile-gate starvation); the two non-matching buckets are struck with notes in `tasks.md` §2.
- Cross-role risk: if a future run's evidence names `tcharl.freeipa_server` or `tcharl.kubernetes` as the failing task's owner, a separate openspec change is raised on that role (monorepo rule 4) instead of editing it here.
